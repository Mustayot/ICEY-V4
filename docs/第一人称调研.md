# 第一人称视角 · 可行性调研(只调查,未实现)

日期:2026-10-07 · 结论先行,证据在后 · 全文没有一行实现代码被合进插件(我写过的临时实现已删除)

---

## 0. 一句话结论

- **真·3D 第一人称:做不到。** ICEY 是 **2D 横版**游戏,场景是分层精灵,**没有 3D 几何**,所以不存在"自由转头看立体世界"。
- **"贴着艾希眼睛往外看"的 2D/2.5D 第一人称:能做,而且不需要碰游戏文件** —— 路径是:用**游戏自己的相机控制器**停掉跟随,把相机挪到头部、拉近、隐藏主角;想要 MC 那种手感,再在**镜头前挂一只手 + 手持物**。
- 但**动手前有 3 件必须实机确认的事**(见第 3 节,每件 10 秒),否则做出来可能不是你要的观感。

---

## 1. 已查实的事实(证据 = 反汇编行号,可复查)

1. **相机大概率是透视的**(我上一句说"正交"是**错的**,这里更正):
   - `CameraController`(类定义 **170703**)自己维护私有字段 `_fieldOfView`(**171203**),它的 setter 只是存值(**171368~171381**);
   - 在 **171390~171401** 附近,`_fieldOfView` 参与一段带常量 `-10`、`0.4537856`(≈26°)、`1.7453292e-2`(≈1°)的**"角度 → 距离"换算** —— 这是**透视相机**的典型做法(用视角算出相机该退多远);
   - 它**从不碰 `orthographicSize`**;真正用 `orthographicSize` 的是另一个类 **`SHICameraController`**(**64618** 读 / **64667** 写)。
   - ⚠ 更正:面板里的「**视野大小**」滑条走的是游戏自己的 `CameraController.FieldOfView`,而这正是游戏**用来控制相机视角**的那个属性 → **它大概率一直是有效的**,不是坏开关(之前那句判断我收回)。
2. **相机每帧由 `CameraController` 摆**(`CameraController::LateUpdate` 存在),但它**自带一个跟随开关** `IsFollowPivot`(public 字段,见 **142462 / 142499** 的 `stfld`)。
   - 面板里的「**自由相机**」就是把它设成 false —— 说明**有正规办法让相机不再听游戏摆布**,不需要去和它抢脚本执行顺序 ✔ 这是第一人称能成立的关键。
3. 游戏另有**相机演出**体系:`CameraFV`(**1498**)、`CameraFVController`(**1560**)(多处调用 `set_FieldOfView`),以及 `TrapCameraLimited`(**4757**,相机限制区)。
   → 过场演出与关卡边界**可能临时抢走/夹住相机** ✗ 这是第一人称最大风险来源。

## 2. 三档方案(按"像不像第一人称"排)

| 方案 | 做法 | 观感 | 量 |
|---|---|---|---|
| **A 贴眼视角** | 相机移到头部 + 关跟随 + 隐藏主角 + 拉近视角 | "从艾希眼睛里平视出去";2D 分层只有少量景深暗示 | 半天 |
| **B 贴眼 + MC 手臂**(最像 MC) | A 之上,加"挂在相机上的手臂 + 手持物",攻击时跟着挥 | **MC 第一人称**那种味道(镜头前一只手臂 + 剑)——方块人素材与剑贴图我们都有 | +半天~1 天 |
| **C 过肩/追尾** | 相机跟在角色后上方一点,不是眼睛位置 | 更接近 3D 游戏手感、更不容易晕,跟方块人很搭 | 半天 |

## 3. 动手前必须实机确认的 3 件事(每件 10 秒,请主人做)

1. **相机到底是透视还是正交**
   打开面板 →「世界与画面」→「相机」→ 把 **`视野大小`** 从 52 拉到 **20** 再拉到 **90**。
   - 画面明显**缩放/透视变化** → **透视**:方案 A/B 观感好(近大远小,分层会"活"起来);
   - **完全没变化** → **正交**:那就改用它内部的 `orthographicSize`,画面会很"平"(但一样能贴眼睛)。
2. **关掉跟随是否生效**
   打开「自由相机」(它把 `IsFollowPivot` 设 false) → 人物走动时相机**不再跟着走** = 这个开关可用 ✔ 第一人称就能把相机"锁"在眼睛上。
3. **演出会不会抢位**
   进一段剧情/过场,看相机是否被抢走(被抢 = 第一人称在过场里会闪一下)。

## 4. 已知风险与固有局限

- **玩法层面(设计问题,不是技术问题)**:第一人称看不见自己的攻击判定、看不见背后来敌;QTE/处决/剧情演出全是按特定机位设计的,第一人称下会错位;
- **关卡边界**:相机可能被 `TrapCameraLimited` 之类的限制区夹住,贴眼视角会被"顶"到边界;
- **必须隐藏主角本体**(面板已有「隐藏原角色」机制,账本可还原),否则视线被自己的头挡住;
- **还原**:关开关时把 `IsFollowPivot` 与视野**写回第一次开启时记下的原值** ✔ 不留下副作用。

---

## 5. 若要做,第一步与验收

- **第一步(建议)**:方案 A —— 一个开关 + `IsFollowPivot=false` + 相机锁眼 + 缩放滑块 + 隐藏主角;
- **验收**:人物跑动/跳跃时,画面像"从艾希眼睛里看";关掉开关,相机立刻回到游戏原状(跟随正常、视野复原);
- **第二步**:方案 B(镜头前手臂 + 手持物,复用方块人的手臂网格与 MC 剑贴图)。

## 6. 结论

**能做,且不碰游戏文件、可一键还原。** 唯一的"做不到"是真 3D 第一人称(游戏没有 3D 场景)。
建议顺序:**先做第 3 节那 3 个 10 秒验证** → 按结果决定是走方案 A 还是直接上方案 B(MC 手臂)。
