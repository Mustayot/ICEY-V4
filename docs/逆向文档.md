## 2. 文件地图(这一节是重点)

### 2.1 `ICEY_Data\` 总览(实测计数)

| 类别 | 数量 | 合计 | 说明 |
|---|---:|---:|---|
| `level*` | **168** | 9MB | **场景文件**(每个关卡/界面一个)。场景里的相机、灯光、摆放的引用都在这里 |
| `sharedassets*.assets` | **168** | 20MB | 与 level 配对的资产头(每个 levelN ↔ sharedassetsN) |
| `sharedassets*.assets.resS` | **119** | **4546MB** | 上面那些资产的**大块像素数据**(纹理)真正躺的地方 |
| `resources.assets` | 1 | 159MB | 全局资源头;**玩家/敌人 Spine、Shader、Sprite 都在这** |
| `resources.assets.resS` | 1 | 464MB | 全局纹理像素 |
| `resources.resource` | 1 | 185MB | 资源包索引 |
| `globalgamemanagers*` | 2 | 1MB | 引擎全局配置;**"总是包含的 shader"清单在这** |
| `*.unity3d` | 0 | — | 没有打包成 bundle,资产是散的 ✔(对我们有利) |

> **关键结论**:关卡资产是**按 168 个 level/sharedassets 分散**的。想改某关的东西,先确定它在哪个 `sharedassetsN` 里
> (用 UnityPy 扫 `resources.assets` 只能覆盖全局资源;关卡内的要在对应的 `sharedassetsN` 里找)。

### 2.2 `ICEY_Data\Managed\`(22 个托管程序集)

| 文件 | 大小 | 里面有什么(与本项目相关的) |
|---|---:|---|
| `Assembly-CSharp.dll` | 1.43MB | **游戏全部逻辑**(玩家/敌人/UI/存档/相机);1707 类型,未混淆 → 我们所有 Harmony 补丁都打在它上面 |
| `Assembly-CSharp-firstpass.dll` | 1.67MB | **I2 Localization**(`I2.Loc.*`,文本/多语言)、**CameraFilterPack**(216 个滤镜,面板里那些)、Spine 的 2D 场景工具(`LineInScene`/`SceneZClamp`/`PropertyInScene`) |
| `Rewired_Core.dll` / `Rewired_Windows_Lib.dll` | 1.94 / 0.83MB | **输入系统**。想"喂假输入"要经过它或游戏自己的输入状态层(见第 5 节) |
| `UnityEngine.dll` / `mscorlib.dll` / `System.*` | — | 用游戏自带的这份编译(C# 走 `csc /noconfig /nostdlib`),**net35** |

反汇编线索:同名 `.il` 文件在 `_moddev\_work\`(`Assembly-CSharp.il` / `Assembly-CSharp-firstpass.il`),
**别整份读**(17MB+),用 `Select-String ... | Select-Object -First N` 定向查。

### 2.3 `resources.assets`(159MB)里都有什么(实测)

| 类型 | 数量/说明 | 我们怎么用的 |
|---|---|---|
| `TextAsset` | Spine 模型:`NewPlayer*.skel`(骨架二进制,**Spine 2.1.27**)、`*.atlas`(布局文本) | 已全部导出到 `_work\model_files\`(见那份 README) |
| `Shader` | **412 个**(`Illumin-*`、`Particles/*`、`Mobile-*`、216 个 `CameraFilterPack_*`…) | 自绘网格时按名字挑;⚠ 引擎"总是包含"的只有 4 个(见 2.6) |
| `Sprite` | 大量 UI/场景精灵 | — |
| `MonoBehaviour` | **2077 个** | ⚠⚠ **`resources.assets` 没有 typetree → UnityPy 读 MonoBehaviour 直接抛异常**
(`Expected to read N bytes, but only read M`)。所以**离线读不到存档/行为树的字段**,要么靠游戏内反射,要么另找带 typetree 的文件 |
| `Texture2D` | 图集(2048²/1024²,DXT5/ARGB32) | 换色就改这些 → 像素在 `.resS` 里,见 2.5 |

> 📌 **全库资源总量**已有一份完整盘点(扫 170 个 `.assets`:22,725 个对象 / 51 种类型 / `AudioClip 2557` /
> `Sprite 1912` / `Shader 429`(明文 ShaderLab)/ `AnimationClip 1001` / `TextAsset 498` / `MovieTexture 30` …),
> 以及"哪些能导出、怎么导"的清单:**见交接文档 §30**(本文件不重复)。

### 2.4 `sharedassetsN` + `levelN`(关卡)

- 敌人/关卡特有的 Spine、图集、贴图、UI 大多在**对应关卡的 sharedassetsN** 里(例如敌人 `Windy`/`Rider` 的骨架);
- 行为树/任务数据:在 `sharedassets0.assets` 里能扫到大量 `StringFriendlyName` / `StringSharedBool*` / `StringNodeDataComment`
  (看命名像 Behavior Designer 之类的行为树框架),以及攻击数据字段名 `SetAtkData` / `atkName` / `AirAtkType` / `AtkBox` / `AtkEffect`。
  → **这暗示攻击/关卡逻辑是"数据驱动"的**(对我们改玩法与做同步都有用)。

### 2.5 `.resS`(4.5GB 的像素数据)

- 纹理的**原始像素**在这里,`.assets` 里只有描述与偏移;我们换贴图就是**同尺寸原地覆盖 `.resS`** ✔ 安全、可哈希校验还原(已做过很多次);
- ⚠ **方向坑**:导出成 PNG 时的行序 = `.resS` 原始行序;而 `Texture2D.LoadImage` 是另一套约定 —— 运行时载入必须**上下翻一次**(我们踩过,见交接文档 14.9)。

### 2.6 `globalgamemanagers.assets`

- 引擎"**总是包含**"的 shader **只有 4 个**:`Sprites/Default`、`Spine/Skeleton`、`Skeleton_PS4`、`SkeletonIllumPlayer_AddNoLight`
  —— **一个都不写深度**(所以自绘 3D 盒子要靠 `Legacy Shaders/Diffuse` 这类能写深度的,或改用排序)。

### 2.7 `StreamingAssets`

| 文件 | 说明 |
|---|---|
| **`sqlite.db`(144KB)** | **数据表**(sqlite-net 读)。改数值/表结构的首选入口 |
| `Movies\ps4\*.mp4` | 过场动画(最大 `atf_jp.mp4` 44MB) |
| `SaveIcon.png` / `PS4SessionImage.jpg` / `TweetUnity.png` | 存档图标与社交分享图 |

### 2.8 根目录

- `ICEY.exe`(20.46MB)、`steam_api64.dll`;
- **Doorstop 注入**:`winhttp.dll` + `doorstop_config.ini` + `.doorstop_version`(我们的 BepInEx 靠它进游戏);
- **`ICEY V4.exe`(14.66MB)= 本项目自己的 GUI 安装器**(源码 `_src\InstallerGui\`,WinForms 全自绘;设计记录见
  `GUI安装器-设计记录.md` 与交接文档 §25),配套还有 `ICEY V4 便携版.zip` / `ICEY V4.7z` / `ICEY V4 源码.zip`。
  → **这不是第三方文件,别当垃圾清掉**;做联机时如果新增依赖,记得同步更新安装器。

## 4. 做联机的现实评估(先说清可行度)

ICEY 是**单人 2D 横版动作**游戏:**没有服务端、没有网络层、没有确定性锁步的基础**。所以:

> ⚠ **先看交接文档 §24**:那条"把 MC 塞进艾希"的 **Passthrough(跨游戏直通)**路线已经**收官判定为不成立**
> (根因是维度:2D 宿主吃不下 3D 客机,且两个游戏系统不互补)。
> **但联机是另一回事** —— 联机不需要 3D 世界几何,只需要**事件与状态同步**,所以下面这条"旁路同步"仍然成立。
> 要复用的是它的**传输形态**(本机 TCP + 换行 JSON),不是它那个目标。

| 路线 | 做法 | 可行度 | 说明 |
|---|---|---|---|
| **A. 旁路同步(推荐)** | 每端各自跑一份游戏;用桥(本机 TCP)交换**玩家位置/朝向/动作/血量/受击事件**,在对方画面里把"另一个玩家"作为**自绘实体**渲染出来(方块人那套渲染器现成) | ★★★★ | 不要求帧级一致、不需要回滚;先把"能看见对方、能互相打"做出来。缺点:敌人不同步(或只同步血量) |
| **B. 状态广播 + 敌人控制权** | 在 A 之上,让"房主"跑权威 AI/敌人,客户端只做表现 | ★★★ | 需要定义"谁算伤害",工作量中等 |
| **C. 帧锁步 / 回滚** | 双方逐帧交换输入并保证结果一致 | ★ | Unity 5.4 + Mono 下 **C# 浮点/物理确定性不保证**,大概率长期处于"漂移就崩"的状态,**不建议先碰** |
| **D. 重写网络层替换游戏主循环** | — | ✗ | 等于重做游戏,不现实 |

### 4.1 ★ 网络能力的硬事实(已用 Mono.Cecil 实测,别重查)

| API | ICEY(Unity 5.4 / Mono .NET 2.0 档) |
|---|---|
| `TcpListener` / `TcpClient` / `Socket` / `NetworkStream` | ✅ **有** → **联机就用本机 TCP + 换行 JSON,零 P/Invoke** |
| 具名 `EventWaitHandle` / `Mutex` / `Semaphore` | ✅ 有(进程间同步可用) |
| `System.IO.Pipes`(命名管道) | ❌ **没有** |
| `System.IO.MemoryMappedFiles`(共享内存) | ❌ **没有**(要用得自己 P/Invoke `CreateFileMappingW`) |
| `Graphics.CopyTexture` / `Blit` / `Texture2D.LoadImage` | ✅ 有(表现层接管画面/贴图可用) |

**推荐开始方式**:照本文件末尾附录提示词的**阶段 1** 做 —— 先让"外部程序驱动游戏里的一个实体",
再把"外部程序"换成"另一台机器的游戏实例" ✔ 传输层同一条路,风险最低。
(注意:那份提示词里的**阶段 3「接真 MC」应视为已否决**,见交接文档 §24;联机不需要 MC。)

## 6. 工具链与工作流(别重复造)

```
# 编译(+ 两项静态自检:①[BepInPlugin]特性 ②元数据里不许混入游戏类型)
powershell -ExecutionPolicy Bypass -File _moddev\_tools\build.ps1            # 装到副本
powershell -ExecutionPolicy Bypass -File _moddev\_tools\build.ps1 -SideBuild # 游戏在跑时编到 _work\
# 打包安装器/便携包
powershell -ExecutionPolicy Bypass -File _moddev\_tools\pack-installer.ps1 -Presets sakura,_blocky
# 图集工具链(导出/调色/区域/回写/校验/还原 + 按语义贴 MC 皮肤)
python _moddev\_tools\atlas_tool.py list|export|palette|atlas|regions|apply|verify|restore|mcskin
# 用日志核对运行时贴图采样
python _moddev\_tools\check-skin-log.py
```

**离线读资源的正确姿势**(UnityPy 1.25.4,已踩过的限制):
- ✅ 能读 `Texture2D` / `TextAsset` / `Shader` 的**名字**(用 `o.read().m_Name`);
- ❌ **MonoBehaviour 读不了**(`resources.assets` 没 typetree)→ 想要数据就查 `sqlite.db` 或从游戏内反射;
- ⚠ 别用 numpy(本机 numpy import 自身就抛 `OverflowError`),解码 DXT 用 `texture2ddecoder` + 切片 `.resS`;
- ⚠ 大文件多(合计 5GB+),扫全库要限流。

**联机相关的网络选择**:先做**局域网直连 socket**(标准库即可),**不要碰 Steam 网络 API**(需要 AppID 权限)。
若以后要上公网,用现成的中继/内网穿透,**别把游戏文件或 SDK 一起分发**。

## 7. 坑清单(接手前必看,都是我们踩过的)

1. **元数据污染会让插件静默失效**:方法签名/字段/特性里出现游戏类型 → BepInEx 丢弃整个 dll,**日志无报错**。用局部变量(`var`)就没事。
2. **别在启动路径做大规模反射**:曾扫"所有程序集所有类型 × 每个方法名用 `AccessTools` 查一遍" → HarmonyX 每次失败写日志 → **8.4MB 日志卡死主线程**(游戏"未响应")。正解:只扫游戏两个程序集 + 每类型一次 `GetMethods(DeclaredOnly)` + 进场景后再装。
3. **等长补丁原则**:资产按"偏移+长度"寻址,改长度 = 重写整个 assets(高风险)。贴图同尺寸覆盖、float 原地覆盖都安全,且要**哈希校验**还原。
4. **`.skel` 是 Spine 2.1.27**(不是 3.x):骨头是"名字 + 定长 float 块"交替内联;`VarInt = 字符数 + 1`;解析时"计数字节后必须紧跟第一条名字且首名是 `root`",否则会把挂件名吃进去。
5. **材质 `_Color` 可能完全不被理会**:主角用的 `Spine/Skeleton IllumPlayer AddNoLight` **不读 `_Color`**(我们改了 7 个材质、原始色白色,画面纹丝不动)。染色要走**顶点色**(拦 `SkeletonRenderer.LateUpdate` 后改 `mesh.colors32`)。
6. **`.resS` 与 `LoadImage` 的行序相反**,运行时载入贴图必须上下翻一次。
7. **`Object.FindObjectsOfType` 每秒别超过 1~2 次**(我们为了藏特效全场扫,踩过性能坑)。
8. **日志要自证**:打印"命中什么/接管几个/拦截几次",否则只能让主人再进一次游戏,成本极高。
9. **绝不许启动/关闭游戏进程**;游戏在跑时只能 `-SideBuild`。

## 8. 建议的分阶段路线(联机版,每阶段可单独验收)

| 阶段 | 内容 | 验收 |
|---|---|---|
| 0 | 读 `交接文档.md` 顶部「给下一个 AI 的 10 分钟入门」+ 本文件;跑通 `build.ps1` | 编译通过、自检两行 ✓ |
