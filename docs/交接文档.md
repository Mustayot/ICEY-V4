## ★ 给下一个 AI 的 10 分钟入门(必读)

**这个项目在干什么**:用 **BepInEx 5 + HarmonyX** 给《ICEY》(Unity 5.4 / Mono / 2D 横版 / 无壳)做**游戏内中文作弊与外观面板**,
外加一整套**"运行时直通"手段**(不改游戏 assets:热换贴图、热换骨架数据、拦调用改行为、自绘网格跟骨架动)。
交付形态是**单文件安装器 exe + 便携 zip**(`_tools\pack-installer.ps1`)。

**六条硬规矩(踩过血)**
1. **绝不许启动/关闭游戏进程**;游戏在跑时只能 `build.ps1 -SideBuild`(产物进 `_work\`,不覆盖插件目录)。
2. **不许改原版游戏文件**(必要时只在副本 `_moddev` 里试);一切改动都要**记账可还原**(写账本,不许靠重扫猜原值)。
3. **等长补丁原则**:游戏资源睡在 `resources.assets` 里按"偏移+长度"寻址 → 只做**等长度覆盖**(贴图同尺寸、float 覆盖),
   要改长度就得重写整个 assets(高风险,现有工具链不做)。还原要**哈希校验**。
4. **别在启动路径做重活**:曾扫"所有程序集所有类型 × 每个方法名用 `AccessTools` 查一遍" → HarmonyX 每次失败写日志 →
   **8.4MB 日志把主线程卡死**(游戏"未响应")。正解:只扫游戏自己的两个程序集 + 每类型一次 `GetMethods(DeclaredOnly)` + 进场景后再装。
5. **一切要能自证**:日志里打印"命中哪个 shader / 接管几个材质 / 拦截几次 / 已染色几次";否则只能让主人再进一次游戏,成本极高。
6. **事实自己查,决策才问主人**:能用反汇编(IL)、UnityPy、日志、Python 验证的,别问。问就问"要哪个",不要问"是不是这样"。

### 手抄 csc 命令(仅当 build.ps1 不好使时)

```powershell
$csc = 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe'
$mdc = 'D:\SteamLibrary\steamapps\common\ICEY\_moddev\ICEY_Data\Managed'
# 如果副本已卸载 BepInEx,就用 _tools 里的原包:
$core = 'D:\SteamLibrary\steamapps\common\ICEY\_moddev\_tools\BepInEx_5.4.23.5_x64\BepInEx\core'
$src = 'D:\SteamLibrary\steamapps\common\ICEY\_moddev\_src\CheatPanel'

& $csc /nologo /noconfig /nostdlib /utf8output /target:library /codepage:65001 /out:"IceyCheatPanel.dll" `
  /reference:"$mdc\mscorlib.dll" /reference:"$mdc\System.dll" /reference:"$mdc\System.Core.dll" `
  /reference:"$mdc\UnityEngine.dll" /reference:"$mdc\Assembly-CSharp.dll" /reference:"$mdc\Assembly-CSharp-firstpass.dll" `
  /reference:"$core\BepInEx.dll" /reference:"$core\0Harmony.dll" `
  "$src\CheatPanelPlugin.cs" "$src\CheatPanelPlugin.Ui.cs" "$src\CheatPanelPlugin.Skin.cs"
```

**要点**
- `/noconfig` 必须加(否则 csc.rsp 会引入 4.0 的 System.dll → CS1703 重复引用)
- `/nostdlib` + 游戏自带 `mscorlib.dll` → 产物引用 `mscorlib 2.0.5.0`,正好匹配 Unity 5.4 的老 Mono
- **`/reference:Assembly-CSharp.dll` 必须加**,漏了的话 `R`、`WorldTime` 全部找不到
- 界面代码用到 `CameraFilterPack_Blur_Movie` → **必须引用 `Assembly-CSharp-firstpass.dll`**
- 中文源码要 `/codepage:65001`(否则中文字符串乱码);加 `/utf8output` 让报错能读

### 安装器 exe(载荷内嵌)

```powershell
$files = Get-ChildItem $pkg -Recurse -File | Sort-Object FullName   # $pkg = _dist\ICEYCheatPanel
$a = @('/nologo','/target:exe','/codepage:65001','/utf8output',"/out:$exe")
$i = 0; foreach ($f in $files) { $a += "/resource:$($f.FullName),f$i"; $i++ }
$a += $gen   # Installer.cs
& $csc @a
```
注意这个 exe **不要**加 `/noconfig /nostdlib`(要用完整 .NET 4 框架)。

## 4. 血泪坑清单(按踩过的顺序,每条都真实发生过)

> ⚠️ **本轮又新增 3 条(第 8~10 条,全是 PowerShell 5.1 + UTF-8 的坑),记在 §29** ——
> 包括"`.ps1` 必须带 BOM"、"绝不能用 PS 文本管道往返改 `.cs` 源码",以及那个
> **不报错但每次都静默丢文件**的载荷缺口(`pack-installer.ps1` 漏拷 `_blocky`)。
> **接手前至少把 §29 扫一眼。**

1. **插件 `Awake()` 里绝对不能碰 Unity API**。在里面调 `Font.CreateDynamicFontFromOSFont` 会让游戏 `0xc0000005` 崩溃(事件日志里"出错模块 ICEY.exe")。字体和贴图一律**延迟到第一次 `OnGUI`**。
2. **`[BepInPlugin]` 特性必须存在**。把类拆成两个 partial 文件时我把它弄丢了,BepInEx 照样扫到文件、照样能加载类型,但报 **`0 plugins to load`**,而且**日志里一句报错都没有**。排查时先 `ildasm /text` 确认这个特性在不在。→ **这是最隐蔽的坑**。
3. **插件元数据里不要出现游戏类型**。方法签名、字段、特性参数(`typeof(游戏类型)`)都算;BepInEx 在 chainloader 阶段扫描,那时 `Assembly-CSharp` 还没加载,可能整个 dll 被丢掉。另外**迭代器里跨 `yield` 持有游戏类型局部变量,编译器会把它提升成迭代器字段**,同样违规 → 一律用 `var` 只在方法体内引用,或把逻辑抽到普通方法里。Harmony 补丁改用 `AccessTools.TypeByName("PlayerJumpAbility")` 按名字解析。
4. **Unity 5.4 必须改 `BepInEx\config\BepInEx.cfg`**:`[Preloader.Entrypoint]` 的 `Type` 从 `Application` 改成 **`MonoBehaviour`**(`Method` 保持 `.cctor`)。不改的后果:游戏脚本全部反序列化失败(日志里 989 次 `different serialization layout` + 2176 次 `script is missing`),**黑屏**。
5. **游戏在跑时 dll 被锁**,csc 会报"请求的操作无法在使用用户映射区域打开的文件上执行"。做法:先编到旁边(`_work\IceyCheatPanel.new.dll`),用后台任务等游戏进程退出后替换,或先让用户关游戏。
6. **`BepInEx\cache\*.dat` 缓存坏了会导致插件不被识别**。删掉它就会重建。
7. **迭代器里 `yield` 不能放在带 `catch` 的 `try` 里**(CS1626)。先做判断,再 yield。
8. **net35 的 `Path.Combine` 只接受两个参数**,4 个参数会编译失败,要嵌套调用。
9. **别自己启动/关闭游戏进程**。我曾用 `Stop-Process ICEY` 收尾,正好把用户正在玩的进程关掉了 —— 用户明确要求不要再这么做。要测就让用户测,或者先问。

16. **本机 `numpy` 和 `UnityPy.export` 一样,`import` 就抛 `OverflowError: cannot convert longdouble infinity to integer`**(Python 3.13 上的同源溢出)。`atlas_tool.py` 刻意不依赖 numpy,图像比较全走 PIL(`ImageChops`/`ImageStat`)。**别给这个项目的 Python 脚本引入 numpy。**
17. **Spine 的 `sharedMaterials` 是按"当前可见附件"重建的**(`SkeletonRenderer::UpdateMesh`),所以自发光页(`_Illum`)、闪光/特效那层**只在某些帧出现在渲染器上**。只靠"几秒扫一次"去发现它们是不可靠的 —— 实机日志的证据:第一版扫描只命中 6 张基础图集,青色的 `PlayerFlash` 光效层一处都没匹配到。**正确姿势:扫描只负责"发现",发现过就累积记住(`_skinKnown`)+ 每帧低成本续写。**
18. **特效贴图的"透明区 RGB"可能是有意义的颜色,不能一律"只改看得见的像素"。** `PlayerFlash` 整张图(含 83% 的 alpha=0 像素)RGB 都是青色,那层光效很可能走加色混合(`Blend One One`,RGB 不乘 alpha)—— 只染 alpha>8 的像素等于没染。所以 `atlas_tool.py palette` 对**文件名含 Flash/Illum 的图**整张染色,对**基础图集**只动 alpha>8 的像素(基础图集的透明区是 (0,4,8) 这种脏数据)。alpha 通道两种情况下都原样贴回。
19. **`Texture2D.LoadImage(byte[], bool)` 的第二参(markNonReadable)有嫌疑**:传 `true` 省一半内存,但实机出现过"换上贴图后人物身体整个不见、只剩残缺光效"的现象(2026-10-07)。已改成传 `false`(保持可读),并且**加了像素采样自检**——载入后把 4 个采样点的 RGBA 写进日志(`[skin] 载入 … 采样: (8,8)=…`),可以拿 PNG 原值逐点核对"上传后内容到底对不对"。这条还**没复验**(等主人实机)。

### 11.1 【已确认】主角的视觉结构 —— 不是 1 个骨架,是 **6 个**

### 14.3 A② 运行时配色 —— 插件第 7 张卡片「配色」(`_src\CheatPanel\CheatPanelPlugin.Skin.cs`)

**材质命中方式(不按骨架槽位,按贴图名)**
1. 扫渲染器:`R.Player.transform.gameObject.GetComponentsInChildren<Renderer>(true)`(含未激活的骨架槽)+ 全场景 `FindObjectsOfType(MeshRenderer/SpriteRenderer)` 兜底,按 instanceID 去重。
2. 对每个渲染器的 `sharedMaterials`,逐个数几个贴图属性(硬编码表:`_MainTex`/`_Illum`/`_IllumTex`/`_EmissionMap`… —— 5.4 没有 `GetTexturePropertyNames()`),先 `HasProperty` 再 `GetTexture`。
3. 贴图名撞 11 个目标名 → 记一条 `(Material, 属性名, 贴图名)`。
   → 基础图集、4 张 `_Illum`、`PlayerFlash` **一次全覆盖**,不需要知道骨架结构、不需要反射私有字段。

**为什么必须改"材质对象本身"**(本次最关键的发现,证据在 IL)
`SkeletonRenderer::LateUpdate` → `UpdateMesh()` 在 113163–113184 每帧都把
`submeshMaterials` 抄进 `sharedMaterials` 并 `meshRenderer.set_sharedMaterials(...)`。
所以 `renderer.material`(实例材质)每帧被丢弃 → **只有改 atlas 素材材质对象的贴图属性才稳**。
好处:还原就是 `SetTexture(属性, 原贴图对象)`,**精确可逆**,不需要重新读原图。

**必须守住的三条不变式**(两轮独立审查抓出来的,改这块前先读)
1. 换上去的 `Texture2D` 要 `t.name = <原贴图名>`。否则下一轮扫描看到的名字对不上目标名单 → 这处材质从 entries 里消失 → **关掉开关也还原不回去**。
2. 原贴图按 **`(材质 instanceID)|(属性名)`** 精确记账(`_skinOrig`),不再按贴图名全局共用一份 ——
   否则两个同名的不同贴图对象会互相"还原成别人的原图",而且那份记录一旦失效就永久静默失效。
   按名字的那份(`_skinOrigFallback`)只当兜底(只记第一个健康的,**不后写覆盖**);取值时校验 `!= null`,失效就剔除。
   另外 `_skinOurs`(我们造过的贴图的 instanceID 集合)**故意永不清理** —— 贴图 Destroy 之后还要靠它认出
   "这处材质挂的是我们的贴图",否则会把我们的贴图误记成原贴图 → 永久还原不回去。
3. **还原的清单是"写入台账" `_skinWrites`,不是 `_skinEntries`。** 每次真的把我们的贴图写进材质就记一条
   (按 `材质instanceID|属性名` 去重)。原因:`_skinEntries` 每轮扫描都 `Clear()` 重建,而扫描只能看到
   **当下存在的渲染器** —— 非激活、又不在玩家层级的渲染器会漏(`FindObjectsOfType` 不返回未激活对象)。
   拿 entries 当清单 → 漏掉的那处贴图会被 Destroy,材质指向已销毁贴图 = 角色糊块,而且死引用会被扫描跳过,**再也修不回来**。

**顺序纪律 + 销毁前复核**:切预设 / 重读 PNG / 关开关时都是
**先 `PushSkinTextures(true)` 把材质写回原贴图 → 再 `FreeSkinTextures()`**;
而 `FreeSkinTextures()` 在 `Destroy` 之前会**拿台账逐条复核**(读不出当前贴图 / 写不回原图 / 原图查不到但当前还挂着我们的贴图 → 计数 +1),
只要有任一条确认不了就**整批不销毁** + 置 `_skinScanned=false` 请求重扫,状态行会如实写"已关闭,但 N 处没还原(看日志 [skin])"。
宁可多占点显存,也不能出现"材质指向已销毁贴图"。

**其它实现要点**
- 全流程 try/catch,异常只写日志 + 状态文字,不抛给 Unity(最外层 catch 也会记前 5 次,不静默)。
- `Awake()` 里只调了 `RefreshSkinPresets()`(纯文件 IO,不碰 Unity API,守坑 #1)。
- `UpdateSkin()` 放在 `Update()` 的 `if (_open) return;` **之前** —— 面板开着也能立刻换色看效果(功能关着时每帧只剩一次 if 判断,不扫)。
- 扫描节奏:命中 0 时退避重试(3s→5s→…上限 12s);命中数还在变 → 2s 一次(骨架在被创建/激活);稳定下来 → 8s 一次(少点 GC 抖动)。
  手动「重新扫描材质」随时立刻扫。
- 载入用 `LoadImage(bytes, true)`(不留 CPU 副本);**`mipChain = false`**:游戏自己的 6 张基础图集槽位**本来就没有 mip 链**
  (`NewPlayerNormal` 槽位 4194304 = 2048×2048×1,正好基础层)→ 不生成 mip 才"和原版一样",还省 1/3 显存。要改就是一个词的事。
- 关掉开关/切预设会 `Destroy` 我们的贴图。**内存提醒**:一张 2048² RGBA 约 16 MB,11 张全用约 130–180 MB —— 不用就关开关。
- PNG 尺寸和原贴图不一致会**告警**(UV 会错位),状态行显示"尺寸不符 N 种";只有"PNG 解码失败"才进黑名单(IO 偶发失败会重试)。

### 14.9 ★根因找到了:运行时贴图**上下方向反了**(2026-10-07 晚,已修)

主人第二张截图(blue 预设)说得很准:**只剩靴子/剑/三角几块残缺贴图,身体整片不见**。

**排查链条(全部有实证,别再重走)**
1. `[skin] 载入 … 采样:` 四个点与 PNG 原值**逐点一致**(6 张贴图全对)→ 排除"上传内容坏掉"。
2. 日志里"没对上的贴图名"= `simpleFlash / white_point32_Sprite / thinRing / falloffLightbeam / distortion3 / Charging / particle11 …`
   → 那层**青光**是"白贴图 + 染色"画的,换贴图换不到它(主人说"青光就是特效不用管",**这条不再追**)。
3. 用 `.atlas` 的区域坐标去量导出的 PNG(处理 `rotate: true` 要互换长宽):
   | 图集 | 区域数 | 不翻:有内容/空白 | **翻过来:有内容/空白** |
   |---|---|---|---|
   | NewPlayerNormal | 120 | 24 / 78 | **109 / 0** |
   | NewPlayerAtk | 130 | 55 / 43 | **113 / 0** |
   | NewPlayerSpAtk | 132 | 61 / 52 | **119 / 0** |
   → 结论:**导出的 PNG 与游戏贴图的行序相反**。

**为什么**
- 导出是把 `resS` 里的 DXT 数据**按行顺序**解出来的 → PNG 第一行 = 数据第一行。
- 而 Unity 贴图的原始数据约定是"第一行在 V=0(下)",Spine 的 UV 也按这个约定算 → 游戏自己那份没问题;
- `Texture2D.LoadImage` 是**按 PNG 约定**摆像素的(让图片在标准 quad 上正着显示)→ 直接塞进去就**整体上下镜像**,
  所有 UV 都采样到镜像区域,于是"只剩几块对称的碎片"。
- **静态那条路(`atlas_tool apply`)不受影响**:它按同样的行序编码回 `resS`,方向天然是对的。

**修法(已实装)**
- `CheatPanelPlugin.Skin.cs`:载入后调 `FlipVertical(t)` —— 用 `GetRawTextureData/LoadRawTextureData` 按行翻转(16MB 一份,比 GetPixels 省 4 倍),`_skinFlip` 默认 **true**。
- 面板第 7 张卡片加了开关「**PNG 上下翻转(必须开)**」—— 万一哪天 Unity 改了 LoadImage 的行为,不用重编译就能翻回来(改开关会整批重新载入贴图)。
- 配置项 `skinflip=1/0` 持久化。

**下一步就是让主人重启验一次**:身体应该完整回来(颜色按预设)。如果**反而更糟**,把开关关掉即回到旧行为,
并把 `[skin] 载入 … 已上下翻/未翻 采样:` 那几行发我 —— 采样点会跟着翻,可以据此判断方向。

## 16. 【任务 B 交付】运行时文本替换(不碰 assets)

**踩过的坑(每个都真炸过)**
1. **朝向 +180°**:Unity 正交 2D 相机在 -Z 往 +Z 看 → 能看到的是盒子**朝 -Z 那一面**。
   把"前脸"贴到 +Z 面 = 玩家看到**后脑勺**(主人第一张截图就是)。

   现在:能改 `_Cull` 的 shader → 设 Off(双面)+ 镜像;不能改的 → **改用偏航角取反**代替镜像。

## 22. 动态配色:第一版失败的原因 + 改走顶点色(2026-10-07)

- **第一版**(改材质 `_Color`)失败,但**日志自证了接管是成功的**:`[fx] 动态配色接管材质 7 个 原始色 RGBA(1.00, 1.00, 1.00, 1.00)`,
  画面却**没有任何变化** → 结论:**这套自定义 shader(`Spine/Skeleton IllumPlayer AddNoLight`)不读 `_Color`**。
- **改走顶点色**(Spine 的着色 = 贴图 × 顶点色;游戏里"打中闪白"用的就是顶点色):
  用 Harmony 在 **`SkeletonRenderer.LateUpdate()`** 上挂 postfix —— Spine 每帧重建网格(顶点色被重置),我们**紧接着**乘上色调,
  保证"重建之后、渲染之前",不依赖脚本执行顺序 ✔
  - 性能:只在色调变化 >1% 时才写一次(避免每帧写 `colors32` 数组 + GC);
  - 还原:顶点色每帧由骨架重新生成 → 关开关下一帧自动恢复,无需记账;
  - 自证:面板「动态配色」的状态行会显示 **"已染色 N 次"** —— 数字在涨=补丁在干活。
- **待主人反馈**:数字涨 + 画面变 = 通;数字涨 + 画面不变 = 这套 shader 连顶点色也不乘,
  下一步就得**换 shader**(用引擎"总是包含"的 `Spine/Skeleton` 顶替,可一键还原)。

| 视频里的效果(GTA5 × MC) | 它靠什么成立 | 艾希 |
|---|---|---|
| MC 画面被 GTA 建筑**正确遮挡** | 宿主深度里有**真 3D 世界几何** | ❌ 深度里只有一张平面背景 + 几个 2D 精灵,**没有可遮挡的对象** |
| GTA 的 **3D 相机**驱动 MC 相机 | 两个都是 3D,相机语义可互换 | ❌ 艾希是 2D 正交跟随相机 |
| GTA 的**地面变成 MC 的碰撞** | 连续 3D 地形可体素化 | ❌ 只能挤成一条 1 格厚的板,**走不出那个平面** |
| Steve 飞 elytra、炸车、和 LAPD 打 | 有可自由活动的开放空间 | ❌ 线性关卡 + 脚本演出 |

**根因不是 2D,是"两个游戏不互补"**:SkyCraft 成立是因为 Skyrim 给"世界/NPC/任务"、MC 给"移动/建造/战斗",
**两个都是富系统且拼起来更强**。艾希是**线性关卡 + 脚本化演出的短流程动作游戏**(没有世界模拟、没有探索、
没有物品栏、没有建造)—— **MC 能给的它一样都不需要,它能给的 MC 一样都用不上。**

**所以准确回答:工程上"能"跑通,产品上"做不到"——做出来的是 demo,不是 mod。**

**顺带三条有用的结论(以后可能用得上)**:
1. **ICEY 侧实测**(Mono.Cecil 反编译):Unity **5.4.0f3** / Mono **.NET 2.0 档**;
   ❌ 没有 `System.IO.MemoryMappedFiles`(要用得自己 P/Invoke `CreateFileMappingW`)、❌ 没有 `System.IO.Pipes`;
   ✅ 有具名 `EventWaitHandle`/`Mutex`/`Semaphore`、✅ 有 `TcpListener`/`TcpClient`/`Socket`/`NetworkStream`、
   ✅ 有 `Graphics.CopyTexture`/`Blit`/`Texture2D.LoadImage`。
   → **本机 TCP + 换行 JSON 是唯一零 P/Invoke 的路**,而且被 universal-modder 的 Terraria `AgentBridge.cs`
   (**2D 游戏** + `TcpListener(Loopback)` + 换行 JSON)反向印证。
2. **2D 宿主做 passthrough 的先例:空白**(系统检索过 guide 02/09 全部参考项目 + 知识库所有 `route=passthrough` 条目,宿主全是 3D)。
3. **通用规律:3D 宿主吃得下 2D 客机;2D 宿主吃不下 3D 客机。** 真要做应该反过来(**MC 当宿主**)。
4. 官方指南里还有一条**官方承认的第二条路**,以后做任何跨游戏合成都用得上:
   mashup-mods 的 Pattern 2 原文 "…and depth buffer, **or spawns host-native objects**" ——
   **唯一那个 Unity 宿主先例 OWCraft 走的正是后者**(把 MC 的 16³ section 直接变成宿主 Unity mesh,HUD 走无深度 overlay)。

**如果还想用 MC 的味道,正确的形态是「内容移植」(无桥)**:即现在的方块人 + MC 素材 + MC 攻击冷却。
**那就是已经在做的形态,而且它是真增益。**

## 29. 【本轮新增】PowerShell 5.1 + UTF-8 的三条铁律(新增血泪坑,接第 4 节)

> 本轮踩了两次,**都是同一个根因**:这台机器上 `powershell -File` / `Get-Content` 默认按 **ANSI(GBK)** 处理 UTF-8。

| # | 坑 | 症状 | 规矩 |
|---|---|---|---|
| 8 | **`_tools\*.ps1` 必须存成 UTF-8 带 BOM** | 无 BOM 时 PS 5.1 按 ANSI 读中文 → 报 `The string is missing the terminator: "`,而且**报错行号指向一个纯 ASCII 行**,极难定位 | **已实测:`build.ps1` 头部就是 `EF BB BF`**,这就是它一直好使的原因。**所有 .ps1 一律带 BOM**;编辑工具改过之后要**补回来** |
| 9 | **绝不能用 PS 文本管道往返改 `.cs` 源码** | `Get-Content -Raw` + `Set-Content -Encoding UTF8` → 中文全坏 → csc 报一堆 **`CS1010 常量中有换行符`** | **改源码一律用编辑器工具**。本轮 `Gui.cs` 就是这么废过一次,只能整份重写 |
| 10 | **csc 编中文源码要 `/codepage:65001`**(老规矩,重申) | 否则中文字符串乱码 | 已在 `build.ps1` / `pack-gui.ps1` 里写好 |

**补 BOM 的一行命令**(照抄):
```powershell
foreach ($p in (Get-ChildItem _tools -Filter *.ps1 -File)) {
  $b=[System.IO.File]::ReadAllBytes($p.FullName)
  if (-not ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)) {
    $t=[System.IO.File]::ReadAllText($p.FullName,[System.Text.Encoding]::UTF8)
    [System.IO.File]::WriteAllText($p.FullName,$t,(New-Object System.Text.UTF8Encoding($true)))
  }
}
```

**另一个本轮修掉的静默缺口**(载入史册级别,因为它**不报错**):
`pack-installer.ps1` 原先只拷 `-Presets` 指定的预设目录,而 `_blocky`(方块人皮肤 + 5 把剑贴图)
是**手工**放进载荷的 → **每次重打包都会静默丢掉**,装到干净机器上方块人就没贴图,而且不报错。
**已修**(脚本现在固定拷 `_blocky` 并打印张数)。载荷因此从 35 → **41 个文件**。
→ **教训:载荷清单一定要在打包时打印出来核对,别信"上次是好的"。**

**还有一个截图工具的坑**:自己写截图/取坐标的 exe 时,**进程必须先声明 DPI 感知**
(启动时 `SetProcessDPIAware()`),否则 `GetWindowRect` 给虚拟化坐标、`CopyFromScreen` 抓物理像素 → **整张图歪掉**。
(和调研笔记里"um win shot 物理像素 vs drive 虚拟坐标"是同一族问题。)
