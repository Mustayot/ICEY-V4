# 解锁 ICEY「官方调试面板」· 实现记录

## 1. 它是什么(全部有一手证据)

游戏自带一套**开发商内部的调试面板**,代码完整地躺在发行版里:

| 部件 | 位置 | 零售版状态 |
|---|---|---|
| `UIDebug`(单例,MonoBehaviour) | 挂在一个叫 **`Debug`** 的 GameObject 上,层级 `UI` → `Debug` → `.Container_debug`(按钮容器) | ✅ **正常加载** |
| **`DebugGUI` 预制体** | `Resources` 路径 **`Prefab/Core/DebugGUI`**,root 上挂 8 个面板组件 | ❌ **从不实例化** |

`DebugGUI` 预制体上的 8 个面板(UnityPy 实测,path_id 6902):

| 组件 | 里面有什么 |
|---|---|
| `GameSettingDebugGui` | **`Cheat On` / `Cheat Off`**、`$+100`、难度 Easy/Normal/Hard/**Hell**、字幕开关、血宫模式、`Open Level Select`、`Full Level`、`Reset Enhancement`、BGM/音效音量 |
| `PlayerAttributeDebugGUI` | **`Full HP` / `Kill All Enemies` / `Kill yourself` / `HP -20` / `PlayerHurtAtk`** |
| `SaveDebugGUI` | `AutoSave` / `AutoLoad` / `DeleteAutoSave` / `Save` / `Load` / `Delete` |
| `GameInfoDebugGUI` | FPS / Physic FPS / 关卡时间 / 场景名 / Mode / `Current AI Status` / frozen frames |
| `EnemyGeneratorDebugGUI` | 刷怪台:`Previous`/`Next`/`Generate`/`Test`/`Isolate`/`ManyTimes`/`Remove` |
| `CameraFVDebugGUI` | FV Settings |
| `CameraFilterDebugGUI` | 相机滤镜:`Add Filter`/`Stop Filter`/`Preview`/`Next` |
| `KeyRebindDebugGUI` | 按键重绑定 |
| (另有) `PlayerEnemyHealth`、`FrozenTimeTest` | 附带组件 |

架构:`Tools.DebugGUIBase : MonoBehaviour` —— `Start()` 里 `UIDebug.Register(get_UIDebugButtonName(), OpenDebugUI)`,
`OnGUI()` 里 `if (openDebugUI) OnDebugGUI()`。基类字段 `openDebugUI` 的 Header 注释是
「是否开启，可以通过设置该值默认开启」。

## 2. 零售版为什么按不出来:两处 `Debug.isDebugBuild()` 硬门槛

**门槛一 —— 预制体根本不加载**(`GameSceneInit.Start()`):
```
IL_003a:  call    UnityEngine.Debug::get_isDebugBuild()
IL_003f:  brfalse IL_005c                        ← release build 直接跳过
IL_0044:  ldstr   "Prefab/Core/DebugGUI"
IL_0049:  call    Resources::Load<GameObject>()  ← 永远走不到
```

**门槛二 —— 就算预制体在,按键也不触发**(`UIKeyInput.UpdateInput()`):
```
IL_0024:  ldsfld  Core.Input/UI::Debug
IL_0029:  callvirt get_OnClick
IL_002e:  brfalse IL_0043
IL_0033:  call    UnityEngine.Debug::get_isDebugBuild()
IL_0038:  brfalse IL_0043                        ← 直接跳过
IL_003d:  call    UIKeyInput::OnDebugClick()
```

## 3. 我们的做法:**不碰游戏代码,一行 Harmony 都没加**

`UnityEngine.Debug.get_isDebugBuild` 是 **native 内部调用**(Mono.Cecil 实测 `HasBody = False`),
Harmony 改不了它本身,只能去改上面那两处调用点的 IL(transpiler)。
**但根本不需要** —— 那两处门槛的**后果**我们可以自己复刻:

| 门槛 | 后果 | 我们的替代动作 |
|---|---|---|
| 门槛一 | 预制体没实例化 | **A. 自己 `Resources.Load("Prefab/Core/DebugGUI")` + `Instantiate` + `DontDestroyOnLoad`**(和 `GameSceneInit` 一模一样的做法)→ 8 个面板的 `Start()` 跑起来,自动注册进**现成的** `UIDebug` 按钮池 |
| 门槛二 | 按键分支被跳过 | **B. 按 F2 时反射调 `UIDebug.Open()` / `Close()`** |

**好处**:不动游戏程序集的任何字节 → 不用记账、不用还原、不存在"改了游戏代码"的风险。

## 4. 为什么全程反射(以及 build 自检为什么不会拦)

`build.ps1` 的第二项静态自检**禁止游戏类型出现在 `.method / .field / .class / .custom` 声明里**
(出现 `Assembly-CSharp` 会被判为"元数据混入游戏类型",BepInEx 会丢整个 dll)。
`UIDebug` 正是 `Assembly-CSharp` 里的类型 → **不能当字段类型、不能当参数类型**。

所以:
```csharp
private Type _tUIDebug;                                  // 用 Type 拿,不用 UIDebug
Assembly asm = typeof(R).Assembly;                       // R 本来就引用了,拿它定位 Assembly-CSharp
_tUIDebug = asm.GetType("UIDebug", false);
UnityEngine.Object[] all = Resources.FindObjectsOfTypeAll(_tUIDebug);   // 比抓 static Instance 稳
```
**实测:编译后自检「元数据里的游戏类型: 0 处 ✓」。**

> 另一条踩坑记录:`Resources.FindObjectsOfTypeAll(Type)` 比 `SingletonMono<UIDebug>.Instance` 稳 ——
> 后者是泛型基类上的静态属性,反射要加 `FlattenHierarchy` 才找得到。

## 5. 怎么用 / 怎么验

1. 装好(跑一遍桌面上的 `ICEY V4.exe`,或 `build.ps1` 装进副本);
2. 进游戏,**按 F2** → 第一次会自动实例化预制体并 `UIDebug.Open()`;
3. 再按 F2 → `Close()`。

**日志自证**(`BepInEx\LogOutput.log`,搜 `[dbg]`):
```
[dbg] 找到类型 UIDebug: UIDebug
[dbg] 官方 DebugGUI 预制体已实例化 —— 10 个组件: GameInfoDebugGUI, GameSettingDebugGui, ...
[dbg] 官方调试面板 Open → 已打开(按 F2 关)
```

## 6. 风险 / 还没验证的

| 风险 | 说明 | 兜底 |
|---|---|---|
| `UIDebug.Register` 按钮池不够 | 按钮来自 `.Container_debug` 的子物体,是个**固定池**。面板多了可能注册失败或串位 | 日志会打出组件数;真不够就只保留要用的几个面板,`Instantiate` 后把多余组件 `Destroy` |
| `_id` 冲突 | `DebugGUIBase._id` 来自 `Register()` 的返回值,若注册失败会都是 0 → IMGUI 窗口 id 撞车 | 同上,是"面板太多"的连带症状 |
| 面板在 IMGUI 里画,和本面板的绘制层次冲突 | 我们的面板也是 `OnGUI`/自绘 | 观察;必要时错开 |
| **F2 是否和游戏自己的键冲突** | 未查 | 冲突就换键(改 `CheatPanelPlugin.cs` 那一行) |
| **只在开发版验证过?** | ❌ **没有**。以上全是静态证据 + 代码推演,**还没有实机跑过** —— 必须主人进游戏按一次 F2 才算数 | 日志搜 `[dbg]` |
