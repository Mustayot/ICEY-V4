### `atlas\` —— **布局表(纯文本)**,13 个
每个 `.atlas` 就是一张"哪块贴图在图集的哪个矩形"的清单,长这样:
```
NewPlayerNormal.png
size: 2048,2048
Idle/Head3
  rotate: false
  xy: 791, 325
  size: 36, 39
  orig: 36, 39
  offset: 0, 0
```
**可以直接用记事本打开看** —— 把 `xy`/`size` 改掉,就能让某个部位改用图集里的另一片。
(注意 `rotate: true` 的区域在图集里是**转置**存放的。`NewPlayerNormal.atlas` 只有 13,524 字节,13 个文件加起来不到 100KB,很好读。)

### `texture\` —— **原始图集 PNG**,14 张
从 `.resS` 里导出的原图(2048²/1024²,带 alpha)。改颜色 = 改这些 PNG,再同尺寸写回(resS 原地覆盖,安全可逆)。

### `_NewPlayerNormal前256字节.txt`
`.skel` 开头的十六进制 + ASCII 对照。你能看到:开头是 hash(长度前缀的字节串)、紧跟着版本字符串 **`2.1.27`**、
两个 float、图片路径 `./Images/`、然后是骨头数量与一根根骨头记录(名字 + 一段二进制数据交替)。

## 这些文件"能不能改"(结论)

| 想改什么 | 改哪个文件 | 可行性 |
|---|---|---|
| 颜色/花纹/服装外观 | `texture\*.png` → 同尺寸写回 resS | ✅ 已在做,可完整还原 |
| 某个部位**改用图集里的哪片图**、偏移、旋转 | `atlas\*.atlas`(文本) | ✅ 可改(等长最稳) |
| **骨骼位置/长度**(腿拉长、头加大)、**网格顶点**(改轮廓)、动画数值 | `skel\*.skel`(二进制) | 🟡 **只能"等长度"原地覆盖数值**;写完要重新解析校验 |
| 加骨头 / 加动画 / 加挂件 / 换拓扑 | — | ❌ 会改变文件长度 → 等于重写整个 assets 结构,高风险,现有工具链没做过 |

**为什么"等长度"是关键**:这三个文件都睡在 `resources.assets` 里,Unity 用"偏移 + 长度"寻址。
你如果让某一段**变长**,后面所有对象的偏移都得重算 —— 那就要重写整个 159MB 的 assets(风险大)。
而 **float 是固定 4 字节**:把 `3.0` 改成 `3.6` 不改变任何长度 → 可以**原地覆盖**,还能一键还原 ✔

**所以"以艾希为基础改建模"的正路是**:
- 想改**轮廓/比例** → 用 `skel` 里的**等长数值补丁**(骨骼位置、顶点、动画值);
- 想换**整套造型** → 运行时不渲染原骨架,自己画网格挂到艾希的骨头上(方块人那条路,已有地基);
- 两条合起来 = 真·换建模。
